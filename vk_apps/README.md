# vk_apps

Утилиты вокруг VK API.

## Задача: первое появление и первое сообщение в беседе

Целевой кейс:

| Что | Значение |
|-----|----------|
| Пользователь | [id37861441](https://vk.ru/id37861441) |
| Беседа | [im/convo/2000000065](https://vk.ru/im/convo/2000000065) → `peer_id=2000000065` |

Скрипт `find_first_message.py` идёт по истории **от самых старых** сообщений и ищет:

1. **Первый вход** — service-сообщение `chat_invite_user` / `chat_invite_user_by_link` (и похожие), где `member_id` = этот пользователь.
2. **Первое сообщение** — первое обычное сообщение с `from_id` = этот пользователь (без `action`).

### Можно ли без регистрации на VK Dev?

**Автоматически через API — нет.**

- `messages.getHistory` требует **пользовательский** `access_token` с правом `messages`.
- Токен выдаётся приложению (Standalone / Implicit Flow). Управление приложениями: [vk.com/apps?act=manage](https://vk.com/apps?act=manage) (это и есть «VK для разработчиков»).
- Право `messages` для пользовательских ключей VK выдаёт **ограниченно** (часто только после запроса в `devsupport@corp.vk.com`).
- Ключ **сообщества** для этой беседы **не подойдёт**: для `peer_id = 2000000000 + chat_id` метод недоступен от имени сообщества.

**Без Dev/токена** остаётся только вручную в клиенте VK: открыть беседу → прокрутить историю вверх / поиск по участнику (если доступен). Скрипт это не заменяет.

Неофициальные «чужие» app_id / парсинг веб-сессии сюда не входят: нестабильно и против правил VK.

### Где взять токен (не путать с «Ключи доступа»)

На странице **Разработка → Ключи доступа** лежат только:

| Ключ | Для чего | Читает беседу? |
|------|----------|----------------|
| Защищённый | `client_secret` / `secure.*` | нет |
| Сервисный | методы без пользователя | нет |

Нужен **ключ доступа пользователя** — его там нет. Его получают через OAuth от имени аккаунта, который состоит в беседе.

Пример для приложения `54818017` («Проверь дату входа»), Standalone / Implicit Flow:

```text
https://oauth.vk.com/authorize?client_id=54818017&display=page&redirect_uri=https://oauth.vk.com/blank.html&scope=messages&response_type=token&v=5.199
```

1. Откройте ссылку, будучи залогинены во ВКонтакте под участником беседы.
2. Разрешите доступ (если VK покажет форму).
3. После редиректа на `https://oauth.vk.com/blank.html#access_token=...&expires_in=...` скопируйте значение `access_token` из адресной строки.
4. Положите в `vk_apps/.env` как `VK_ACCESS_TOKEN=...` — **не присылайте токен в чат**.

Важно про `scope=messages`:

- для **новых** приложений право `messages` VK **часто не выдаёт**;
- в доках прямо сказано: для новых приложений это право не выдаётся; раньше — через поддержку `devsupport@corp.vk.com`;
- без `messages` скрипт упрётся в ошибку доступа к `messages.getHistory`.

Тип приложения должен позволять пользовательский OAuth (Standalone / настроенный VK ID). Сервисный и защищённый ключи для этой задачи не подставляйте.

### Запуск

```bash
cd vk_apps
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# впишите VK_ACCESS_TOKEN=...

python find_first_message.py
# или явно:
python find_first_message.py --user-id 37861441 --peer-id 2000000065 --token "$VK_ACCESS_TOKEN"
```

Полезные флаги:

- `--max-messages 5000` — ограничить объём скана
- `--json-out report.json` — сохранить отчёт
- `--sleep 0.5` — пауза между запросами (антифлуд)

Выход: JSON с `first_join` и `first_message` (дата, id сообщения, превью).

### Ограничения

- Нужен аккаунт, у которого есть доступ к этой беседе.
- История может быть неполной (удаления, лимиты, старые чаты).
- Если человека добавили без видимого action в доступной истории, `first_join` может не найтись — тогда ориентир только `first_message`.
